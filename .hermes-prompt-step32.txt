Implement Step 32: AND/OR logic toggle for multi-filter expressions

## What to Build

Add a toggle in the filter panel that switches between AND and OR logic for combining multiple filters. Currently all filters are hardcoded to AND. The user needs the ability to switch to OR mode so multi-filter expressions can match any condition instead of all conditions.

Add `filterLogic: 'AND' | 'OR'` state (default: 'AND') and a `setFilterLogic(logic: 'AND' | 'OR')` function.

Update the `UseFiltersReturn` interface to include:
- `filterLogic: 'AND' | 'OR'`
- `setFilterLogic: (logic: 'AND' | 'OR') => void`

Update the exported interfaces:
- Export a `FilterLogic` type: `'AND' | 'OR'`
- Add `filterLogic` to `UseFiltersOptions` with default 'AND'

CRITICAL: Update `combinedFilter` useMemo to join active filter parts with the current `filterLogic` instead of hardcoded " AND ". The baseFilter should always be AND'd to the user filter logic group (use parentheses for the user filters when logic is OR).

Specifically:
- If filterLogic is 'AND': `parts.join(" AND ")` (same as today)
- If filterLogic is 'OR': Wrap user filter parts in parentheses and AND with baseFilter: `baseFilter AND (userFilter1 OR userFilter2)`
- When there is a baseFilter AND user filters with OR logic: combine as `baseFilter AND (userFilter1 OR userFilter2 OR ...)`
- The baseFilter always AND-combines with user filters

```typescript
describe("useFilters - filterLogic", () => {
  it("defaults to AND logic", () => {
    const { result } = renderHook(() => useFilters());
    expect(result.current.filterLogic).toBe("AND");
  });

  it("setFilterLogic changes the logic", () => {
    const { result } = renderHook(() => useFilters());
    act(() => { result.current.setFilterLogic("OR"); });
    expect(result.current.filterLogic).toBe("OR");
  });

  it("uses OR logic when set to OR", () => {
    const { result } = renderHook(() => useFilters());
    act(() => {
      result.current.addFilter("A", "a = 1");
      result.current.addFilter("B", "b = 2");
    });
    act(() => { result.current.setFilterLogic("OR"); });
    expect(result.current.combinedFilter).toBe("(a = 1 OR b = 2)");
  });

  it("combines baseFilter with OR user filters: baseFilter AND (userFilter1 OR userFilter2)", () => {
    const { result } = renderHook(() => useFilters({ baseFilter: "deleted = false" }));
    act(() => {
      result.current.addFilter("A", "status = 'Active'");
      result.current.addFilter("B", "amount > 0");
    });
    act(() => { result.current.setFilterLogic("OR"); });
    expect(result.current.combinedFilter).toBe(
      "deleted = false AND (status = 'Active' OR amount > 0)"
    );
  });

  it("single active filter with OR logic does not wrap in parens", () => {
    const { result } = renderHook(() => useFilters());
    act(() => { result.current.addFilter("A", "a = 1"); });
    act(() => { result.current.setFilterLogic("OR"); });
    expect(result.current.combinedFilter).toBe("a = 1");
  });
  
  it("wraps multiple OR filters in parentheses even without baseFilter", () => {
    const { result } = renderHook(() => useFilters());
    act(() => {
      result.current.addFilter("A", "a = 1");
      result.current.addFilter("B", "b = 2");
      result.current.addFilter("C", "c = 3");
    });
    act(() => { result.current.setFilterLogic("OR"); });
    expect(result.current.combinedFilter).toBe("(a = 1 OR b = 2 OR c = 3)");
  });
});
```

## Key Design Decisions

1. **baseFilter always ANDs with user filter group** — The baseFilter is a system-level filter (like "deleted = false") that should always apply. When user filters are OR mode, the combination is `baseFilter AND (userFilter1 OR userFilter2)`.

2. **Parenthesize OR groups** — When filterLogic is OR and there are 2+ user filters, wrap them in parentheses to ensure correct SQL precedence.

3. **Single filter doesn't need parens** — When there's only 1 user filter, OR vs AND doesn't matter, so don't add unnecessary parentheses.

4. **The toggle is in the expanded filter panel** — Placed between the filter list and the Add Filter section, consistent with the spec mockup showing "Logic: [AND ▼] all filters must match".

5. **URL persistence includes logic** — The logic setting is serialized into the URL so it survives page reloads and can be shared.
