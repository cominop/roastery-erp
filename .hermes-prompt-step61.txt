## What to Build for Step 61

### 1. SQL Migration — `nav_tree` table

Create `/home/fcc-student/Desktop/_DEV/roastery-ui/server/sql/step-61-nav-tree-table.sql`:

```sql
CREATE TABLE IF NOT EXISTS shared.nav_tree (
  id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  parent_id       UUID REFERENCES shared.nav_tree(id),
  type            TEXT NOT NULL CHECK (type IN ('group','catalog','journal','detail','report','dashboard')),
  table_id        TEXT,
  caption         TEXT NOT NULL,
  icon            TEXT,
  sort_order      INTEGER NOT NULL DEFAULT 0,
  visible         BOOLEAN NOT NULL DEFAULT true,
  role_visibility TEXT[],
  badge_field     TEXT,
  badge_color     TEXT,
  created_at      TIMESTAMP DEFAULT NOW(),
  updated_at      TIMESTAMP DEFAULT NOW()
);
```

Wrap in `BEGIN;` / `COMMIT;` block. Use `IF NOT EXISTS` so it's idempotent.

### 2. Seed data — populate nav_tree with current sidebar structure

After creating the table, INSERT seed data that matches the existing sidebar. Query the database to discover:
- Tables from `db_fcc_erp` schema
- Forms from `shared.objects WHERE type = 'form'`
- Reports from `shared.objects WHERE type = 'report'`

Create a seed function or script that:
1. Creates a root group "Navigation Tree"
2. Creates "Catalogs" group → catalogs from db_fcc_erp (tables that are static reference data: customers, products, employees, suppliers, etc.)
3. Creates "Journals" group → transactional tables (orders, work_orders, invoices, purchase_orders, etc.)
4. Creates "Details" group → subform tables (order_details, invoice_lines, etc.)
5. Creates "Reports" group → reports from shared.objects
6. Creates "Dashboards" group (empty initially)
7. Each leaf node gets `table_id` set to the actual table name
8. Sets `sort_order` for each node

The seed data should be in the same SQL file as the CREATE TABLE, wrapped in the same transaction.

Look at the actual database tables and forms to create appropriate groups. You can query the DB:
- `SELECT tablename FROM pg_tables WHERE schemaname = 'db_fcc_erp' AND LEFT(tablename, 1) != '_' ORDER BY tablename`
- `SELECT DISTINCT name, definition->>'caption' as caption FROM shared.objects WHERE type = 'form' AND definition IS NOT NULL ORDER BY name`
- `SELECT DISTINCT name, definition->>'caption' as caption FROM shared.objects WHERE type = 'report' AND definition IS NOT NULL ORDER BY name`

### 3. API endpoint — GET /api/nav-tree

Modify `server/index.cjs` to add a new endpoint `GET /api/nav-tree` that:

1. Queries `shared.nav_tree` ordered by `sort_order`
2. Groups by `parent_id` to build a tree structure
3. Returns a nested JSON tree:
```json
{
  "id": "...",
  "type": "group",
  "caption": "Catalogs",
  "children": [
    {
      "id": "...",
      "type": "catalog",
      "caption": "Customers",
      "table_id": "customers",
      "icon": null,
      "sort_order": 0,
      "visible": true,
      "role_visibility": null
    }
  ]
}
```

4. Only include nodes where `visible = true`
5. The root query should return top-level nodes (parent_id IS NULL)
