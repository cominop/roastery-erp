## Database Schema Reference
```sql
-- Report definitions table
CREATE TABLE shared.report_definitions (
    id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    name            VARCHAR(255) NOT NULL,
    caption         VARCHAR(255),
    category        VARCHAR(100),
    template_file   VARCHAR(255),
    output_formats  TEXT[] DEFAULT '{pdf}',
    source_table    VARCHAR(255),
    filterable      BOOLEAN DEFAULT false,
    parameters      JSONB DEFAULT '[]',
    bands           JSONB DEFAULT '{}',
    visible_to_roles TEXT[] DEFAULT '{}',
    auto_generate   JSONB,
    enabled         BOOLEAN DEFAULT true,
    created_at      TIMESTAMPTZ DEFAULT NOW(),
    updated_at      TIMESTAMPTZ DEFAULT NOW()
);

-- Schedule log table
CREATE TABLE shared.report_schedule_log (
    id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    report_id       UUID NOT NULL REFERENCES shared.report_definitions(id),
    report_name     VARCHAR(255) NOT NULL,
    scheduled_at    TIMESTAMPTZ NOT NULL,
    generated_at    TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    format          VARCHAR(10) NOT NULL,
    output_path     TEXT,
    recipients      TEXT[],
    status          VARCHAR(20) NOT NULL DEFAULT 'success',
    error_message   TEXT,
    file_size_bytes BIGINT,
    created_at      TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
```

## What to Build

### Goal
Create a bulk migration tool that automates the conversion of the remaining 97 Access reports to the new report system. The tool should handle both the metadata generation (report definitions) and the template creation (.ods files).

### Implementation Order

#### 1. Create `server/reports/access_migration.py`
A Python script that:
- Reads Access report definitions from the existing MDB file (`/home/fcc-student/Desktop/ACCESS_DB/` — find the actual .accdb or .mdb file)
- Uses `mdbtools` (check if installed, install if needed: `sudo apt-get install mdbtools -y`)
- Exports the list of Access reports with their metadata (name, query source, parameters)
- Generates a migration manifest JSON file listing all reports to migrate

The script should:
```python
#!/usr/bin/env python3
"""
access_migration.py — Bulk migration tool for Access reports.

Usage:
  python3 server/reports/access_migration.py --scan              # Scan Access DB for report definitions
  python3 server/reports/access_migration.py --generate-manifest # Generate migration manifest
  python3 server/reports/access_migration.py --migrate N        # Migrate N reports (batch)
  python3 server/reports/access_migration.py --migrate-all      # Migrate all remaining reports
  python3 server/reports/access_migration.py --status            # Show migration status

Output:
  - server/reports/migration/access-reports.json  # Full scan results
  - server/reports/migration/manifest.json         # Migration manifest
  - server/reports/migration/progress.json         # Migration progress tracker
  - server/sql/step-98-migration.sql               # SQL migration for any new tables
"""
```

Key features:
1. **Scan Access DB**: Use `mdb-tables` and `mdb-schema` to list all tables/queries that are report sources
2. **Generate manifest**: Create a JSON manifest with one entry per Access report, mapping to:
   - Report name → report definition name
   - Source table/query → source_table
   - Parameters → report parameters array
   - Category → heuristically determined from name
3. **Batch migration**: For each report in the manifest:
   - Create a basic .ods template with %(marker)s placeholders
   - Register the report definition in the DB
   - Mark as migrated in the progress tracker
4. **Status tracking**: Keep a progress.json file showing which reports are migrated, pending, or failed

```sql
-- Migration progress tracking table
CREATE TABLE IF NOT EXISTS shared.report_migration_log (
    id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    report_name     VARCHAR(255) NOT NULL,
    access_name     VARCHAR(255),
    category        VARCHAR(100),
    template_file   VARCHAR(255),
    definition_id   UUID REFERENCES shared.report_definitions(id),
    status          VARCHAR(20) NOT NULL DEFAULT 'pending',  -- pending | migrated | failed | skipped
    error_message   TEXT,
    started_at      TIMESTAMPTZ,
    completed_at    TIMESTAMPTZ,
    created_at      TIMESTAMPTZ DEFAULT NOW()
);

CREATE INDEX idx_report_migration_status ON shared.report_migration_log (status);
CREATE INDEX idx_report_migration_category ON shared.report_migration_log (category);
```
