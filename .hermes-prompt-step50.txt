Section 9.1 Cache Strategy:
```typescript
// LRU cache with TTL per field
const calcCache = new LRUCache<string, any>({
  max: 500,
  ttl: 30_000,    // 30 seconds
});

function getCalculatedField(table: string, field: string, recordId: number, context: any) {
  const cacheKey = `${table}:${field}:${recordId}`;
  if (calcCache.has(cacheKey)) {
    return calcCache.get(cacheKey);
  }
  const result = evaluateExpression(table, field, context);
  calcCache.set(cacheKey, result);
  return result;
}
```

## What to Build

### 1. Server-side: `server/calculated_fields/calc_cache.py`
A Python LRU cache module with 30s TTL:

```python
# LRU cache with TTL for aggregate calculation results
class CalcCache:
    def __init__(self, max_size: int = 500, ttl_seconds: int = 30):
        ...
    def get(self, key: str) -> Any | None:
        """Return cached value if exists and not expired."""
    def set(self, key: str, value: Any) -> None:
        """Cache a value with current timestamp."""
    def invalidate(self, key: str) -> None:
        """Remove a specific key from cache."""
    def invalidate_all(self) -> None:
        """Clear all cached values."""
    def invalidate_table(self, table_name: str) -> None:
        """Invalidate all cache entries for a given table (key prefix match)."""
```

Key considerations:
- Use dict-based LRU (simple move-to-front on access)
- TTL is per-key, checked on get()
- Thread-safe using threading.Lock
- Keys should have format: `{table_name}:{calc_field_name}:{record_id}`

### 2. Server-side: Aggregate Evaluation Endpoint in `server/index.cjs`

Add a new route: **POST /api/calculated-fields/evaluate-aggregate**

This route:
1. Accepts `{ table_name, expression, record_id, parent_field_name }` in the body
2. Parses the aggregate expression to identify:
   - The aggregate function (SUM, COUNT, AVG, MIN, MAX)
   - The related table (e.g., `order_details` from `SUM(order_details.{quantity})`)
   - The field expression within the aggregate (e.g., `quantity * unit_price`)
3. Builds a SQL query to:
   - JOIN the current record's table with the related table
   - Apply the relationship (parent table's key → child table's foreign key)
   - Compute the aggregate function over the related records
4. Executes the SQL query against PostgreSQL
5. Returns the result
6. Wraps the result in CalcCache with 30s TTL (cache key: `{table_name}:{field_name}:{record_id}`)
7. Handles errors gracefully

**Relationship resolution heuristic:**
- For `SUM(order_details.{field})` on table `orders`:
  - The related table is `order_details`
  - The foreign key is likely `order_id` (parent table name + `_id`)
  - We need to query: `SELECT SUM(field_expression) FROM order_details WHERE order_id = $1`
- For COUNT with no field expression: `COUNT(*)`
- For other aggregates: `AVG(expr)`, `MIN(expr)`, `MAX(expr)`

**Important:** Extract the field expression (inside {} braces) and resolve it to the actual column name. The expression uses Jam.py-style `{field_name}` references that resolve to the related table's columns.

### 3. React-side: API Client Update (`src/calculated-fields/api/calculatedFieldsApi.ts`)

Add a new function:
```typescript
export interface AggregateResult {
  result: number | null;
}

export function evaluateAggregate(
  tableName: string,
  expression: string,
  recordId: number,
): Promise<AggregateResult> {
  return request<AggregateResult>('/calculated-fields/evaluate-aggregate', {
    method: 'POST',
    body: JSON.stringify({
      table_name: tableName,
      expression,
      record_id: recordId,
    }),
  });
}
```

### 4. React-side: Update `useCalculatedFields` Hook

Update the hook at `src/calculated-fields/hooks/useCalculatedFields.ts`:

The current hook evaluates scalar/formula expressions using the client-side `evaluateExpression` function. For `calcType === 'aggregate'`, we need to:

1. Detect fields with `calcType === 'aggregate'`
2. For aggregate fields, call the `/evaluate-aggregate` API endpoint instead of the client-side evaluator
3. Use a separate cache (dictionary) per table+field+record to avoid redundant API calls within a session
4. Handle loading/error states per aggregate field
5. Support auto-refresh when the record ID changes

**Architecture:**
- Scalar/formula fields: continue using client-side `evaluateExpression()` (existing behavior)
- Aggregate fields: use the new server-side `/evaluate-aggregate` endpoint
- The hook should call all aggregate evaluations in parallel (Promise.all)
- Non-aggregate fields should still use the existing memo-based evaluation

```typescript
// Updated return type — add aggregateResults
interface UseCalculatedFieldsResult {
  computedValues: Record<string, unknown>;
  definitions: CalculatedField[];
  loading: boolean;
  error: string | null;
}
```

**Important:** The `currentRecord` parameter used to be a full record object. For aggregate evaluation, we need a record ID. Update the hook to also accept an optional `recordId` parameter, or extract the `id` field from `currentRecord`.
