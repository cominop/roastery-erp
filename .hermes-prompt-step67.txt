## Existing Code Structure

### Backend API (in server/index.cjs)
All CRUD endpoints already exist:
- `GET /api/nav/tree?visible_only=true&company_id=1` — get full tree (flat list, depth/path)
- `POST /api/nav/tree` — create node (body: parent_id, label, icon, target_type, target_name, target_params, sort_order, is_visible, is_expanded, color, badge)
- `PUT /api/nav/tree/reorder` — batch reorder (body: { siblings: [{id, sort_order}] })
- `PUT /api/nav/tree/:id` — update node (partial update)
- `DELETE /api/nav/tree/:id` — delete node (cascade deletes children)
- `GET /api/nav/tree/:id` — get single node
- `GET /api/permissions/user` — returns { userId, roleIds, roleNames, isAdmin }
- `GET /api/nav/tree/counts?company_id=1` — live record counts
- `GET /api/nav/tree/status-badges?company_id=1` — status badges

### Database (shared.nav_tree)
```sql
CREATE TABLE shared.nav_tree (
  id             SERIAL PRIMARY KEY,
  parent_id      INTEGER REFERENCES shared.nav_tree(id) ON DELETE CASCADE,
  label          VARCHAR(255) NOT NULL,
  icon           VARCHAR(100),
  target_type    VARCHAR(50) NOT NULL DEFAULT 'group'
                  CHECK (target_type IN ('group', 'table', 'form', 'report', 'link', 'divider')),
  target_name    VARCHAR(255),
  target_params  JSONB,
  sort_order     INTEGER NOT NULL DEFAULT 0,
  is_visible     BOOLEAN NOT NULL DEFAULT true,
  is_expanded    BOOLEAN NOT NULL DEFAULT true,
  color          VARCHAR(50),
  badge          VARCHAR(50),
  company_id     INTEGER NOT NULL DEFAULT 1,
  created_at     TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  updated_at     TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
```

## What to Build

### Step 67: Nav Editor Panel (add/remove/reorder nodes, admin only)

Create a nav editor panel that allows admin users to visually edit the navigation tree. This includes adding new nodes, removing existing nodes, and reordering siblings.

### The NavEditorPanel Component

Create `src/components/navigation/NavEditorPanel.tsx`:

**Props:**
```typescript
interface NavEditorPanelProps {
  tree: NavTreeNode[];        // Full tree (not filtered by visibility)
  onTreeChange: () => void;   // Callback to refresh tree after changes
  isAdmin: boolean;           // Whether the current user is admin
}
```

**Layout:**
- A slide-out panel or modal overlay (but NOT a full-page redirect)
- Use a Sheet component (like the existing Settings panel uses `Sheet` from `@/components/ui/sheet`)
- The panel should have a header "Edit Navigation" with a close button
- To open it, add an "Edit Navigation" button in the sidebar footer, next to the Settings button, but ONLY visible to admin users

**Features:**

#### 1. Display the tree in editor mode
- Show the full tree hierarchy (including hidden nodes, all nodes regardless of visibility)
- Each node shows:
  - Icon (resolved from `resolveIcon` in SidebarTree or a default)
  - Label
  - Target type badge (small tag showing "group", "table", "form", etc.)
  - Visibility toggle (checkbox/switch to toggle `is_visible`)
  - Move up / Move down buttons (to reorder siblings)
  - Delete button (with confirmation — use a simple confirm dialog or a shadcn AlertDialog)

#### 2. Add a new node
- An "Add Node" button at the bottom of the panel, or an "Add" button within each group
- Clicking opens a sub-form/dialog:
  - Parent selector: dropdown of all existing groups (type="group") to choose where to add
  - Label: text input (required)
  - Target type: dropdown (group, table, form, report, link, divider)
  - Target name: text input (optional, shown only when target_type is not 'group' or 'divider')
  - Icon: text input (optional, icon name from ICON_MAP in SidebarTree)
  - Color: color picker (optional)
  - Badge: text input (optional)
  - Sort order: number input (optional, auto-computed to append if empty)
  - Submit creates node via POST /api/nav/tree

#### 3. Remove a node
- Delete button on each node
- Confirmation dialog: "Are you sure you want to delete '{label}'? This will also delete all children."
- On confirm: DELETE /api/nav/tree/:id
- On success: refresh tree

#### 4. Reorder siblings
- Move Up / Move Down buttons on each node
- Move Up: swap sort_order with the previous sibling
- Move Down: swap sort_order with the next sibling
- After reorder: call PUT /api/nav/tree/reorder with the updated sibling order
- Disable "Move Up" on the first sibling, "Move Down" on the last sibling

#### 5. Edit node properties inline
- Clicking a node label or having an edit button opens an inline edit form
- Allow editing: label, icon, target_type, target_name, is_visible, is_expanded, color, badge
- On save: PUT /api/nav/tree/:id with the updated fields
- On cancel: discard changes
