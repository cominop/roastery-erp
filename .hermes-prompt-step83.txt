Implement Step 83: Metadata Deployment 4 — Import: UPSERT all metadata types

## Objective
Extend the existing `server/metadata-importer.cjs` (which currently only VALIDATES archives) to actually UPSERT all 7 metadata definition files into the target database tables. After validation succeeds (Steps 1-7 in the existing code), perform the actual import.

## What Exists
1. **server/metadata-export.cjs** — Serialises all metadata FROM the database into JSON files under `src/metadata/export/definitions/`
2. **server/metadata-packager.cjs** — Packages JSON files into a .zip with manifest.json, version.txt, checksums.sha256
3. **server/metadata-importer.cjs** — Currently only validates the archive (manifest structure, checksums, file completeness, JSON parse). Does NOT write to the database yet.
4. **src/metadata/export/definitions/** — Contains: forms.json, fields.json, events.json, nav_tree.json, permissions.json, reports.json, settings.json

## Database Connection
The project uses PostgreSQL via `pg` module. Connection pattern from existing code:
```js
const { Pool } = require("pg");
const pool = new Pool({ database: "polyaccess" });
```

## UPSERT Logic Required
Extend `server/metadata-importer.cjs` with a new "--import" mode that, after validation passes:

### For each definition file, do:
1. **forms.json** → UPSERT into `shared.forms` table
   - Match on: `name` (form name is unique)
   - INSERT: id, database_id, name, definition (JSONB), record_source, description, version, is_current, created_at, owner, modified_by
   - UPDATE: definition (JSONB), record_source, description, version, is_current, modified_by, modified_at = NOW()
   - Also handle legacy form objects in `shared.objects` WHERE type = 'form' — same UPSERT by name

2. **fields.json** → UPSERT into `field_definitions` (or create it if it doesn't exist)
   - The fields data from the exporter has: form_name, section, sub_section, control_name, control_type, control_source, caption, definition (JSONB)
   - Create a `shared.field_definitions` table if it doesn't exist:
     ```sql
     CREATE TABLE IF NOT EXISTS shared.field_definitions (
       id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
       form_name TEXT NOT NULL,
       section TEXT DEFAULT 'root',
       sub_section TEXT DEFAULT 'detail',
       control_name TEXT NOT NULL,
       control_type TEXT DEFAULT 'unknown',
       control_source TEXT,
       caption TEXT,
       definition JSONB,
       created_at TIMESTAMP DEFAULT NOW(),
       modified_at TIMESTAMP DEFAULT NOW()
     );
     ```
   - UPSERT on (form_name, control_name) — update definition JSONB, control_type, caption

3. **events.json** → UPSERT into `shared.event_handlers`
   - Match on: id (or create new if not exists)
   - INSERT: id, form_name, event_name, handler_type, handler_code, sort_order, enabled, scope, created_at
   - UPDATE: handler_code, enabled, sort_order, modified_at = NOW()

4. **nav_tree.json** → FULL REPLACE of `shared.nav_tree` (per spec: "nav_tree.json → REPLACE nav_tree (full tree swap)")
   - DELETE FROM shared.nav_tree WHERE 1=1 (clear all)
   - INSERT all records from the JSON data
   - Wrap in a transaction for atomicity

5. **permissions.json** → UPSERT into permissions tables
   This is a complex JSON object with sub-keys: roles, user_roles, table_permissions, field_permissions, row_filters
   
   a) **roles** → UPSERT into `shared.roles` by id
   b) **user_roles** → UPSERT into `shared.user_roles` by id
   c) **table_permissions** → UPSERT into `shared.table_permissions` by (role_id, table_name)
   d) **field_permissions** → UPSERT into `shared.field_permissions` by (role_id, table_name, field_name)
   e) **row_filters** → UPSERT into `shared.row_filters` by id

6. **reports.json** → UPSERT into report definitions
   - Create `shared.reports` table if not exists (id UUID, name TEXT, definition JSONB, type TEXT, ...)
   - UPSERT by name

7. **settings.json** → UPSERT into settings/appearance
   - Into `shared.objects` WHERE type = 'appearance' — UPSERT by name

### Conflict Resolution (from spec Section 6.2)
| Scenario | Behaviour |
|----------|-----------|
| New form in import, not in current DB | Added |
| Form in current DB, not in import | Left untouched (no auto-delete) |
| Form in both, different layout | Overwritten |
| Field type changed | Warning — may break data integrity |
| Role missing | Added (new role) |
| Role removed | Not deleted (data safety) |

### After All UPSERTS
1. Invalidate all caches — set a flag or clear in-memory state
2. Log the import result with counts (how many added, updated per type)
3. Save import record to `shared.metadata_imports` table (create it if not exists):
   ```sql
   CREATE TABLE IF NOT EXISTS shared.metadata_imports (
     id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
     filename TEXT NOT NULL,
     checksum TEXT NOT NULL,
     imported_by UUID,
     imported_at TIMESTAMP DEFAULT NOW(),
     status TEXT DEFAULT 'completed',
     forms_added INTEGER DEFAULT 0,
     forms_updated INTEGER DEFAULT 0,
     fields_added INTEGER DEFAULT 0,
     fields_updated INTEGER DEFAULT 0,
     events_added INTEGER DEFAULT 0,
     events_updated INTEGER DEFAULT 0,
     error_log TEXT,
     import_log TEXT
   );
   ```

## CLI Usage
Add a new `--import` flag:
```bash
node server/metadata-importer.cjs --archive deploy/erp_metadata_2026-07-30.zip --import
```

When `--import` is passed, the tool:
1. Runs ALL validation steps (existing code)
2. If validation passes, performs the UPSERT pipeline
3. Reports counts per type: "✓ forms.json: 88 added, 12 updated"
4. If validation FAILS, exits with error without importing

## Code Quality
- Wrap each table UPSERT in try/catch so one type failing doesn't kill the whole import
- Use transactions (BEGIN/COMMIT/ROLLBACK) for the nav tree REPLACE
- Progress logging: print each file being processed
- Error logging: collect errors per file and report at end
- Exit code 0 on success, 1 on failure
- Handle the case where tables don't exist yet — CREATE TABLE IF NOT EXISTS for any table that might be missing
