## What to Build

### Step 66: Status Badges (pending orders, low stock indicators)

Add status badges to the nav tree. Unlike count badges (which show total record counts), status badges show items that need attention — with color-coded severity indicators.

### Backend

1. Create `server/sql/step-66-status-badges.sql` — a new SQL migration that adds:

   a. **`shared.fn_nav_tree_status_badges(p_company_id INTEGER DEFAULT 1)`** — Returns status badge info for nav tree nodes that have a `badge_field` set. The function should:
      - Read the nav_tree nodes and their `badge_field` values
      - Support these built-in badge types:
        | badge_field | Query | Severity | Example |
        |-------------|-------|----------|---------|
        | `pending_orders` | `SELECT COUNT(*) FROM db_fcc_erp.orders WHERE status = 'pending'` | danger | 🔴 [12] |
        | `low_stock` | `SELECT COUNT(*) FROM db_fcc_erp.products WHERE stock <= reorder_level` | warning | 🟡 [5] |
        | `unfilled_orders` | `SELECT COUNT(*) FROM db_fcc_erp.orders WHERE filled = false` | danger | 🔴 [3] |
        | `overdue_orders` | `SELECT COUNT(*) FROM db_fcc_erp.orders WHERE due_date < NOW() AND status != 'completed'` | danger | 🔴 [7] |
      - For nodes WITHOUT a badge_field, return no status badge (null)
      - Return: `(node_id UUID, badge_field TEXT, badge_count BIGINT, severity TEXT)`
      - Use `EXECUTE` for dynamic SQL per badge_field type
      - Return 0 for counts when no matching records (don't show badge for 0)

   b. **Register the API endpoint** in `server/index.cjs`:
      ```
      GET /api/nav/tree/status-badges?company_id=1
      Response: { [nodeId: string]: { count: number, severity: 'danger' | 'warning' | null } }
      ```
      - MUST be defined BEFORE the `/api/nav/tree/:id` route (like the counts endpoint)
      - Cache results for 30 seconds in-memory (simple module-level cache with timestamp)

### Frontend

2. **Update `src/components/SidebarTree.tsx`** to accept and render status badges:

   a. Add a new prop: `statusBadges?: Record<string, { count: number; severity: 'danger' | 'warning' | null }>`
   
   b. In `TreeNodeRow`:
      - After the count badge, if there's a status badge for this node, render a colored indicator:
        - danger severity: 🔴 `[N]` in red
        - warning severity: 🟡 `[N]` in yellow
        - Don't show if count is 0
      - Use Tailwind classes: `bg-red-100 text-red-700 dark:bg-red-900/30 dark:text-red-400` for danger
      - And `bg-yellow-100 text-yellow-700 dark:bg-yellow-900/30 dark:text-yellow-400` for warning
   
   c. In `NavGroup`:
      - Aggregate status badges from children and show a summary indicator
      - If any child has danger status, show 🔴 on the group header
      - If any child has warning status (no danger), show 🟡 on the group header

3. **Update `src/App.tsx`** to fetch status badges:
   - Add a new state: `const [statusBadges, setStatusBadges] = useState<Record<string, { count: number; severity: string }>>({});`
   - Add a new useEffect that polls `/api/nav/tree/status-badges?company_id=1` every 60 seconds
   - Pass `statusBadges={statusBadges}` to the SidebarTree component
