## Context

## What to build
Create the server-side filter-to-SQL translation layer. This has two parts:

### Part A: Python module — `src/filters/server/filter_to_sql.py`
Create a Python module with a function `filters_to_where_clause(filters, logic='AND')` that converts filter state objects into SQL WHERE clause fragments with parameterised values.

The function signature should be:
```python
def filters_to_where_clause(
    filters: list[dict],
    logic: str = 'AND'
) -> tuple[str, dict]:
    """Convert filter states to a SQL WHERE clause fragment with params dict.
    
    Args:
        filters: List of active filter state dicts, each with:
            - field_name (str): The DB column name
            - operator (str): One of the FilterOperator values
            - value: The filter value(s)
            - active (bool): Whether the filter is enabled
        logic: 'AND' or 'OR' — how multiple filters combine
    
    Returns:
        (where_clause, params_dict) — where_clause includes "WHERE " prefix,
        or ("", {}) if no active filters
    """
```

Supported operators (from the spec):
- `equals` → `field = %(name)s`
- `not_equals` → `field != %(name)s`
- `contains` → `field ILIKE %(name)s` (value wrapped in `%...%`)
- `starts_with` → `field ILIKE %(name)s` (value wrapped in `...%`)
- `ends_with` → `field ILIKE %(name)s` (value wrapped in `%...`)
- `greater_than` → `field > %(name)s`
- `less_than` → `field < %(name)s`
- `greater_equal` → `field >= %(name)s`
- `less_equal` → `field <= %(name)s`
- `range` → `field BETWEEN %(name_from)s AND %(name_to)s` (value is [from, to])
- `in_list` → `field = ANY(%(name)s)` (value is a list)
- `not_in_list` → `field != ALL(%(name)s)` (value is a list)
- `is_null` → `field IS NULL` (no param needed)
- `is_not_null` → `field IS NOT NULL` (no param needed)
- `custom` → raw expression (value IS the SQL fragment, no param)

### Part B: API endpoint — add to `server/index.cjs`
Add a POST endpoint `/api/filters/to-sql` that:
1. Accepts JSON body: `{ filters: [...], logic: 'AND' }`
2. Calls the Python module via subprocess (following the same pattern as `sandbox-runner.py`)
3. Returns `{ success: true, sql: "...", params: {...} }` or `{ success: false, error: "..." }`

The server spawns the Python script like this:
```javascript
const { spawn } = require('child_process');
// Call: python3 src/filters/server/filter_to_sql.py with JSON on stdin
// Read JSON result from stdout
```

### Part C: Client-side API function — `src/lib/api.ts`
Add a function:
```typescript
export async function filtersToSql(
  filters: { field_name: string; operator: string; value: any; active: boolean }[],
  logic?: 'AND' | 'OR'
): Promise<{ sql: string; params: Record<string, any> }>
```

That POSTs to `/api/filters/to-sql`.
