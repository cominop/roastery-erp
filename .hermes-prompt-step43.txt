## What to build

### 1. Expression Evaluator (`server/calculated_fields/expression_evaluator.py`)

Create a Python module that evaluates an AST (from `parse_expression()`) against a context dictionary (record data with field values) and returns the computed result.

**Core interface:**
```python
def evaluate(ast: Expression, context: EvalContext) -> Any: ...
def evaluate_expression(expression: str, context: EvalContext) -> Any: ...
```

Where `EvalContext` is:
```python
@dataclass
class EvalContext:
    record: dict[str, Any] = field(default_factory=dict)       # Current record field values
    all_records: list[dict[str, Any]] | None = None             # All records (for aggregates)
    group_records: list[dict[str, Any]] | None = None           # Group records (for aggregates)
    user_context: dict[str, Any] = field(default_factory=dict)  # User info, company, etc.
```

**AST evaluation logic:**

1. **FieldRef** — Look up the field name in `context.record` (case-insensitive). Return `None` if not found.
   - Also support table-qualified refs: `{table.field}` → lookup in context if available

2. **LiteralNode** — Return the literal value as-is

3. **BinaryOp** — Evaluate left and right, then apply operator:
   - `+`: numeric addition (coerce both to number)
   - `-`: numeric subtraction
   - `*`: numeric multiplication
   - `/`: numeric division (return None for division by zero)
   - `&`: string concatenation (Access-style `&` operator, convert to string, null → "")

4. **Comparison** — Evaluate left and right, then compare:
   - `=`: equal (Access-style: return -1 for True, 0 for False)
   - `!=` / `<>`: not equal
   - `>`, `<`, `>=`, `<=`: numeric comparisons
   - All comparisons return -1 (True) or 0 (False) per Access convention

5. **UnaryOp** — Evaluate operand, then apply:
   - `-`: numeric negation
   - `NOT`: logical NOT (truthy check → 0 or -1)

6. **Logical operations** (these are represented as BinaryOp with "AND" / "OR" operators and UnaryOp with "NOT"):
   - AND: truthy check both sides → -1 or 0
   - OR: truthy check either side → -1 or 0
   - NOT: negate truthiness → -1 or 0

7. **FunctionCall** — Look up function name (case-insensitive) and call it with evaluated args

**Access-style truthiness:**
- `None` / null → False
- Number 0 → False
- Empty string "" → False
- Everything else → True

**Access-style number coercion (toNumber):**
- Already a number → return as-is
- String → parseFloat (0 if NaN)
- Boolean → -1 for True, 0 for False
- None/null → 0

**Built-in functions to support (all case-insensitive):**

Conditional:
- `IIF(condition, true_part, false_part)` — if truthy(condition) return true_part else false_part
- `NZ(value, [alt])` — return value if not null, else alt (default 0)
- `ISNULL(value)` — return -1 if null/empty, else 0

Date/time:
- `NOW()` — return current datetime
- `DATE()` — return current date
- `DATEADD(interval, count, date)` — add interval to date (d=day, m=month, yyyy=year)
- `DATEDIFF(interval, date1, date2)` — difference between dates
- `YEAR(date)` — extract year
- `MONTH(date)` — extract month
- `DAY(date)` — extract day

String:
- `LEFT(str, count)` — leftmost N chars
- `RIGHT(str, count)` — rightmost N chars
- `MID(str, start, count)` — substring (1-indexed start)
- `LEN(str)` — string length
- `TRIM(str)` — trim whitespace
- `UCASE(str)` — uppercase
- `LCASE(str)` — lowercase
- `INSTR(str, substr, [start])` — find substring position (1-indexed, 0 if not found)
- `REPLACE(str, old, new)` — replace all occurrences
- `CONCAT(str1, str2, ...)` — concatenate strings

Math:
- `INT(num)` — floor
- `ABS(num)` — absolute value
- `VAL(str)` — convert string to number (0 if invalid)
- `ROUND(num, [precision])` — round to decimal places
- `MIN(num1, num2, ...)` — minimum
- `MAX(num1, num2, ...)` — maximum

Aggregate (operate on context.group_records or context.all_records):
- `SUM(field_expr)` — sum of field across records
- `COUNT(expr)` — count (COUNT(*) counts all rows)
- `AVG(field_expr)` — average
- `MIN(field_expr)` — minimum across records
- `MAX(field_expr)` — maximum across records

Format:
- `FORMAT(value, format_str)` — basic formatting:
  - "Currency" → "$1,234.50"
  - "Percent" → "25.00%"
  - "Fixed" → "3.14"
  - "Short Date" → "6/15/2024"

### 2. Error Handling

Create `server/calculated_fields/eval_error.py`:
```python
class EvalError(Exception):
    """Error raised during expression evaluation."""
    def __init__(self, message: str, detail: str = ""):
        self.message = message
        self.detail = detail
        super().__init__(f"#Error: {message}" + (f" ({detail})" if detail else ""))
```

For any evaluation error (division by zero, missing function, type error, etc.), the evaluator should catch the exception and return the string `"#Error"`.

## Important notes

- No eval(), exec(), compile() — the evaluator walks the AST tree directly
- Follow Access-style conventions: comparisons return -1/0, truthiness is Access-style
- Use Python 3.11+ features (dataclasses, type hints)
- Field lookup must be case-insensitive (Access convention)
- Division by zero should return None (not raise)
- Functions are case-insensitive
- The evaluator should catch any unexpected errors and return "#Error" string
- Read `src/lib/expressions.ts` for reference on how each function and operator behaves
- The `&` operator is string concatenation (not bitwise AND)
- Aggregate functions use `context.group_records` (fall back to `context.all_records`)
