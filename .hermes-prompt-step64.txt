## What to build

### 1. Add `role_visibility` column to nav_tree table
Create a DB migration SQL file at `server/sql/step-64-role-visibility.sql` that:
- Adds `role_visibility TEXT[]` column to `shared.nav_tree` (NULL = visible to all, non-empty array = only these role names can see it)
- Updates `shared.fn_nav_tree()` to accept a 3rd parameter `p_role_names TEXT[] DEFAULT '{}'` and filter nodes:
  - If role_names is empty or contains 'admin' → show all nodes (admin bypass)
  - Otherwise, a node is visible if:
    - Its role_visibility IS NULL (visible to all), OR
    - Its role_visibility overlaps with the provided role_names array
  - Children of a hidden group node should also be hidden (cascade visibility)
- Apply it: `psql -d polyaccess -f server/sql/step-64-role-visibility.sql`

### 2. Update API endpoint
In `server/index.cjs`, update the GET /api/nav/tree handler:
- Accept a new query param `?role_names=admin,manager` (comma-separated role names)
- Pass it to `shared.fn_nav_tree($1, $2, $3)` — the 3rd param is the role_names array
- Default to empty array if not provided (shows all)

### 3. Update client-side nav tree fetching
In `src/App.tsx`:
- Import `usePermissions` from `@/hooks/usePermissions`
- Use it to get the current user's role names
- Include role_names in the API call: `fetch("/api/nav/tree?visible_only=true&company_id=1&role_names=admin,manager")`
- The tree should re-fetch when user info loads

### 4. Update seed data

- All admin link items (Table Permissions, Calculated Fields, Event Handlers, Audit Log) → role_visibility = '{admin}'
