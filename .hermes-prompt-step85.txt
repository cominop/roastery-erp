## What was built

### 1. SQL table — `shared.metadata_backups`
**File:** `server/sql/step-85-metadata-backups.sql`
- Creates the `shared.metadata_backups` table with columns: id (UUID PK), path, created_at, reason, size_bytes, checksum
- Indexes on created_at DESC and reason for fast listing/filtering

### 2. `server/metadata-backup.cjs` — CLI backup script
**File:** `server/metadata-backup.cjs`
- Runs the export pipeline (metadata-exporter.cjs) to get current metadata from DB
- Packages it into a .zip archive with auto-backup naming: `auto-backup-YYYY-MM-DD-HHMMSS-before-import.zip`
- Records the backup in `shared.metadata_backups` table
- Supports `--reason <reason>` (default: "pre_import"), `--output <path>`, `--json` (machine-readable output), `--verbose`
- Usage:
  ```bash
  node server/metadata-backup.cjs --reason manual
  node server/metadata-backup.cjs --reason pre_import --json
  ```

### 3. `server/metadata-importer-upsert.cjs` — `--backup` flag
- Added `--backup` flag that triggers an automatic backup before the import runs
- Backup runs after validation passes but before the UPSERT phase
- Non-fatal — if backup fails, a warning is logged and import continues
- Skips backup in dry-run mode

### 4. API endpoints in `server/index.cjs`
- `POST /api/metadata/backup` — creates a metadata backup. Optional body: `{ "reason": "manual" }`
  - Runs export + package pipeline, records in DB
  - Returns 201 with the backup record
- `GET /api/metadata/backups` — lists all backups newest first
  - Query params: `?limit=20`, `?reason=pre_import`
  - Returns array of backup records
