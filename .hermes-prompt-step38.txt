## What to Build

Build the **Permission Matrix Editor** — the admin UI where an administrator can:
1. Select a role
2. Select a table
3. Set table-level CRUD permissions (Select, Insert, Update, Delete)
4. Set field-level permissions per field (ReadWrite, ReadOnly, Hidden)
5. Set row-level filter SQL
6. Save everything for that role+table combination

## Architecture

### File to Create: `src/permissions/admin/PermissionMatrix.tsx`

The component should have this layout (matching the spec in Section 8):

```
+-- Permission Matrix ---------------------------------------------+
|  Role: [Manager v]     Table: [Products v]                       |
|                                                                    |
|  +-- Table Actions -------------------------------------------+   |
|  |  [x] Select  [x] Insert  [x] Update  [ ] Delete            |   |
|  +-------------------------------------------------------------+   |
|                                                                    |
|  +-- Field Permissions ----------------------------------------+  |
|  |  Field Name       | Access v                                |  |
|  |  name             | ReadWrite v                             |  |

|  |  cost_price       | ReadOnly v                              |  |

|  |  stock_qty        | ReadWrite v                             |  |
|  |  margin           | Hidden v                                |  |
|  +-------------------------------------------------------------+  |
|                                                                    |

|  +---------------------------------------------------------------+ |

|  [Save]  [Reset to Defaults]                                       |
+--------------------------------------------------------------------+
```

### Backend API: Add to `server/index.cjs`

The server currently has:
- GET /api/permissions/fields/:table — gets field-level perms for current user
- GET /api/permissions/user — current user
- POST /api/permissions/check — check table permission
- GET /api/nav — lists tables, forms, reports
- GET /api/schema/:table — column metadata for a table

You need to add:

1. **GET /api/permissions/matrix?role_id=X&table=Y** — Returns current permissions for a role+table:
   ```json
   {
     "table_permissions": { "can_select": true, "can_insert": true, "can_update": false, "can_delete": false },
     "field_permissions": { "name": "readwrite", "cost_price": "readonly", "margin": "hidden" },
     "row_filter": { "condition": null, "filter_sql": null, "enabled": false }
   }
   ```
   Query shared.table_permissions, shared.field_permissions, and shared.row_filters.

2. **PUT /api/permissions/matrix** — Save permissions for a role+table:
   Body:
   ```json
   {
     "role_id": 1,
     "table": "products",
     "table_permissions": { "can_select": true, "can_insert": true, "can_update": true, "can_delete": false },
     "field_permissions": { "name": "readwrite", "cost_price": "readonly", "margin": "hidden" },
     "row_filter": { "condition": "assigned_to = current_user", "filter_sql": "assigned_to = current_user()", "enabled": true }
   }
   ```
   UPSERT logic: INSERT ON CONFLICT DO UPDATE for table_permissions. For field_permissions, delete existing for this role+table and re-insert. For row_filters, upsert.
