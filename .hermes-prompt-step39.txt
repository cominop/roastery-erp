## What needs to be built for Step 39

### A) Backend — Row Filter API endpoints (server/index.cjs)

Add these endpoints AFTER the existing /api/permissions/matrix routes (around line 1020):

1. **GET /api/permissions/row-filters/:role_id/:table_name** — Get a single row filter for a role+table combination
   - Returns the row filter entry or null if not found
   - Query the shared.row_filters table

2. **POST /api/permissions/row-filters** — Upsert a row filter
   - Body: { role_id, table_name, filter_sql, description }
   - Uses ON CONFLICT (role_id, table_name, company_id) DO UPDATE

3. **DELETE /api/permissions/row-filters/:id** — Delete a row filter by id
   - Returns { ok: true } on success

### B) Backend — Integrate row filter into data queries (server/index.cjs)

In the GET /api/data/:table route (around line 164), AFTER building the WHERE clause with user filters and BEFORE executing the query:

1. Import `applyRowFilter` from `./permission-middleware.cjs` (if not already imported — it's already imported alongside permissionGuard)
2. Call `applyRowFilter(table, req.user.roleIds, req.user.companyId)` to get any row-level filter SQL fragment
3. If a filter fragment is returned, append it to the WHERE clause with AND
4. Handle the case where req.user might be undefined (no permission middleware ran — e.g., admin bypass)

Also update the GET /api/data/:table/:id single-record endpoint to apply row filters.

### C) Frontend — Row Filter UI (src/permissions/admin/PermissionMatrix.tsx)

Add a "Row Filter" section to the Permission Matrix editor. This should be:

1. A collapsible section below the main field grid (or as a secondary panel)
2. For the currently selected role and table, show:
   - A textarea where admins can enter a SQL WHERE clause fragment (e.g., "assigned_to = current_user_id" or "sales_rep_id = (SELECT employeeid FROM db_fcc_erp.employees WHERE user_id = current_user_id)")
   - A description field explaining what this filter does
   - An enabled/disabled toggle
   - Save and Reset buttons
3. When a different role is selected in the dropdown, load that role's row filter for the current table
4. Add a dropdown to select which role the row filter applies to (reuse the existing role selector or add one if needed)

The UI should match the spec's Section 8 mockup:
```
│  ┌─ Row Filter ───────────────────────────┐  │
│  │  Only show rows where:                 │  │
│  │  [assigned_to = current_user      ]    │  │
│  │  ── or leave blank for all rows ──      │  │
│  └───────────────────────────────────────┘  │
```
