## What to Build
Add live count badges to tree nodes. Each node in the nav tree should show a count badge next to its label. The badge system supports:

1. **Record count badges** — `[156]` next to catalog nodes showing total records in the table
2. **Pending item badges** — 🔴 `[12]` next to order nodes showing pending/attention-needed items
3. **Custom SQL badges** — defined per node via `badge_field` in the nav_tree

### Backend

Create a new API endpoint (or extend the existing nav tree endpoint) that returns badge counts for all nodes:

```sql
GET /api/nav/badges
Response: { [nodeId: string]: { count: number, status: 'info' | 'warning' | 'danger' | null } }
```

The endpoint should:
- For each nav_tree node, if `badge_field` is set, use it to determine the count query
- For nodes without `badge_field`, default to `SELECT COUNT(*) FROM <table_id>` where table_id is the node's linked table
- Support special badge_field values like `pending_orders`, `low_stock` etc.
- Return counts for ALL nodes (frontend filters what to show)
- Cache results for 30 seconds (simple in-memory cache)

### Frontend

1. **`useNavBadge` hook** (typically `src/components/navigation/hooks/useNavBadge.ts`) — fetches badges from the API, polls every 60 seconds, returns a map of nodeId -> { count, status }

2. **`NodeBadge` component** (typically `src/components/navigation/NodeBadge.tsx`) — renders the badge:
   - Shows `[N]` for standard count badges
   - Shows colored dot + count for status badges (🔴 for danger, 🟡 for warning)
   - Shows nothing if count is 0 for status badges
   - Small, compact, positioned after the node label

3. **Integrate into `SidebarTree`** — each node renders its badge from the badge map
