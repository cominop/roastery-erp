Implement Step 73: Visual Editor — Phase 3 — TabsBandEditor (tab bar, bands, per-band field picker)

## What to build

Create the `TabsBandEditor` component for the Visual Editor. This is the tab + band hierarchy editor that maps to Access form grouping. It manages tabs (each with a caption) and bands within each tab (each with a set of fields).

### Mockup
```
┌─ Tabs ───────────────────────────────────────┐
│  [Customer Info]  [Address]  [Orders]   +    │
│  ┌─── Band 1 ─────────────────────────────┐  │
│  │  Customer Name  |  Email               │  │
│  │  Phone          |  Status              │  │
│  └────────────────────────────────────────┘  │
│  ┌─── Band 2 ──── +Add ───────────────────┐  │
│  │  Assigned To   |  Group               │  │
│  └────────────────────────────────────────┘  │
│  [Tab options: rename | delete]              │
└──────────────────────────────────────────────┘
```

### Features required
1. **Tab bar**: click to select active tab, "＋" button at end to add a new tab
2. **Tab rename**: double-click on tab caption → inline edit (input replaces text, Enter/blur saves)
3. **Tab delete**: small "×" close button on each tab (except prevent deleting the last tab)
4. **Bands per tab**: each tab shows its bands as bordered sections
5. **Each band has a FieldPicker**: nested field selection using the existing FieldPicker component
6. **Band "＋Add" button** at bottom of each tab to add a new band
7. **Band delete button** (X) in top-right corner of each band (unless it's the last band in the tab)
8. **Drag-to-reorder tabs**: use HTML5 drag and drop on the tab bar

### Component API
```typescript
interface FormTab {
  id: string;
  caption: string;
  bands: FormBand[];
}

interface FormBand {
  id: string;
  fields: FieldRef[];
}

interface FieldRef {
  fieldId: string;
  visible: boolean;
}

interface TabsBandEditorProps {
  tabs: FormTab[];
  onChange: (tabs: FormTab[]) => void;
  /** All fields available for selection (passed to each band's FieldPicker) */
  availableFields: { name: string; type: string }[];
  disabled?: boolean;
}
```

### Implementation approach

1. **State management**: The component is fully controlled via `tabs` prop + `onChange` callback. Generate unique IDs with `crypto.randomUUID()` or a simple counter.

2. **Tab bar rendering**: Render a horizontal bar with tab buttons. The active tab gets a highlighted style. Each tab has a caption and a small "×" delete button (hidden on hover until focused).

3. **Tab rename (double-click)**: On double-clicking a tab caption, replace the <button> with an <input>. On Enter key or blur, commit the new caption via onChange. On Escape, cancel.

4. **Inline field editing** (per the per-band FieldPicker): For each band, embed a compact FieldPicker. The FieldPicker's `availableFields` is all fields minus those already used in other bands of the same tab. The `selectedFields` is the band's own fields.

   For the FieldPicker integration, you'll need to compute the available fields per band as: allAvailableFields minus (fields already selected in other bands of the same tab), so the same field can't appear in two bands simultaneously. This is a UX decision — the parent can also handle it, but it's cleaner inside the component.

5. **Drag-to-reorder tabs**: Implement HTML5 DnD with `draggable`, `onDragStart`, `onDragOver`, `onDrop` on tab elements. Show a visual indicator during drag.

### Key guidelines
- Keep the component self-contained (no external state management)
- Use `cn()` from `@/lib/utils` for className merging
- Use lucide-react icons (Plus, X, GripVertical for drag handle)
- Compact, consistent styling with existing components (text-[11px], small padding, hover states)
- Every band has exactly one FieldPicker
- Tab reorder via HTML5 DnD (no external library needed)
- The component should handle edge cases: empty tabs array, empty bands, single tab, many bands
- Import FieldPicker from `../FieldPicker` and its type from `../FieldPicker`
- Use `useId()` from React for accessible form labels if needed
