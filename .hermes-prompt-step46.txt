## What to build

### 1. Python dependency analyzer → `server/calculated_fields/dependency_analyzer.py`
A module that can extract field dependencies from a calculated field expression string.

Key capabilities:
- **`extract_field_references(expression: str) -> list[str]`** — Extract all `{field_name}` references from the expression string. These are fields the calculated field depends on within the same table.
- **`extract_table_references(expression: str) -> list[tuple[str, str]]`** — Extract table-qualified field references like `table_name.{field_name}` from aggregate function arguments (SUM, COUNT, AVG, MIN, MAX) and LOOKUP calls. Returns list of (table_name, field_name) tuples.
- **`extract_all_dependencies(expression: str) -> dict`** — Combines both, returning `{"depends_on": [...], "depends_on_tables": [...]}`.
- Handle edge cases: nested braces, escaped braces, string literals containing braces, empty expressions, expressions with no field references.

### 2. Update API routes in `server/index.cjs`
The existing PUT /api/calculated-fields/:id and POST /api/calculated-fields routes should:
- After parsing the body, call the Python dependency analyzer via child_process.execFileSync (same pattern used in existing calculated fields API routes)
- Auto-populate `depends_on` and `depends_on_tables` if they weren't explicitly provided in the request body
- If they WERE explicitly provided, use the provided values (manual override)

### 3. Tests → `server/__tests__/test_dependency_analyzer.py`
Test cases:
1. Empty expression → empty dependencies
2. Simple field refs: `{quantity} * {unit_price}` → depends_on: ["quantity", "unit_price"], depends_on_tables: []
3. With string literals: `{first_name} + " " + {last_name}` → depends_on: ["first_name", "last_name"]
4. Aggregate with table ref: `SUM(order_details.{quantity} * order_details.{unit_price})` → depends_on: ["quantity", "unit_price"], depends_on_tables: ["order_details", "order_details"] or just ["order_details"]
5. LOOKUP: `LOOKUP(customers.{name}, {customer_id})` → depends_on: ["customer_id"], depends_on_tables: ["customers"]
6. Complex expression with mixed refs, functions, literals
7. Expression with no refs at all: `42`
8. Edge: braces in string literals like `"hello {world}"` — should NOT detect `world` as a field ref
9. Edge: function with no arguments: `TODAY()` → no dependencies

### 4. Integration test for the API auto-population
Add a test that:
- Creates a calculated field via POST without explicitly providing depends_on/depends_on_tables
- Verifies the response includes auto-populated depends_on and depends_on_tables
