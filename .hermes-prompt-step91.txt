Implement Step 91: Reports 2 — Report definition table + API

We're building a band-oriented report generation system for the Roastery ERP. Step 90 (already complete) built the Python rendering engine (marker_parser.py, band_processor.py, renderer.py with .ods fill, CLI entry point for PDF/CSV/XLSX export via LibreOffice headless).

Now implement the database table and CRUD API for report definitions.

## What to build

### 1. Database Migration

Create a migration file (server/migrations/reports/) that creates the `report_definitions` table with these columns (based on the ReportDefinition interface from the spec):

```typescript
interface ReportDefinition {
  id: string;              // Primary key, UUID
  name: string;            // Unique slug-like name (e.g., 'invoice', 'customer-statements')
  caption: string;         // Human-readable title
  description: string;     // Optional description
  category: string;        // Group/category (e.g., 'Financial', 'Inventory', 'Production', 'Other')
  template_file: string;   // Path to .ods template file relative to templates/ directory
  output_formats: string[]; // e.g., ['pdf', 'csv', 'xlsx', 'html']
  source_table: string;    // FK to a DB table name (the primary data source)
  filterable: boolean;     // Whether to show parameter entry before render
  parameters: jsonb;       // Array of ReportParameter objects
  bands: jsonb;            // Object with title/header/detail/summary/footer/cover band configs
  visible_to_roles: string[]; // Array of role names that can see this report
  auto_generate: jsonb;    // Optional ScheduleConfig object
  enabled: boolean;        // Whether this report is active
  created_at: timestamptz;
  updated_at: timestamptz;
}
```

Add appropriate indexes (category, name, enabled).

Create a seed script that inserts placeholder entries for the most common report categories (Financial: Invoice, Invoice Summary, Credit Note, Customer Statement, Sales by Customer; Inventory: Inventory List, Stock Valuation, Low Stock Alert, Inventory Movement; Production: Work Order, Roast Log, Batch Yield Report, Production Schedule).

### 2. API Endpoints (server/reports/api/ directory or similar)

Create Express router with:
- `GET /api/reports` — List all reports the user has access to (filtered by visible_to_roles), with optional category/format/enabled filters and search by name/caption
- `GET /api/reports/:id` — Get single report definition by ID
- `POST /api/reports` — Create new report definition (admin only)
- `PUT /api/reports/:id` — Update report definition (admin only)
- `DELETE /api/reports/:id` — Soft-delete (set enabled=false, admin only)
- `GET /api/reports/categories` — List distinct categories

All endpoints should check permissions:
- Read: any authenticated user with the report in their visible_to_roles
- Write: admin role only

### 3. TypeScript types

Create or update `src/reports/schema/reportSchema.ts` with the exported type definitions matching the database schema, plus Request/Response types for the API.

### 4. API client

Create or update `src/reports/api/reportsApi.ts` with fetch calls to all the API endpoints. Use the existing API client pattern (see src/events/api/eventHandlersApi.ts or similar for reference).
