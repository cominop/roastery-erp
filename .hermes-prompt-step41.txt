Implement Step 41 — Seed default permissions for all 7 built-in roles

## Context

We've built a full RBAC permission system across Steps 33-40. All the DB tables exist (roles, user_roles, table_permissions, field_permissions, row_filters), the middleware is in place, and the permission cache with 5-min TTL is working.

The current DB only has 5 roles seeded (admin, manager, data-entry, read-only, reports). The Permissions spec (Section 3.1) defines 7 built-in roles:

| Role | Typical user | Access scope |
|------|-------------|--------------|
| admin | Peter, system admin | Everything |
| manager | Operations manager | All data, no system config |
| roaster | Roastery staff | Production, inventory, products |
| sales | Sales team | Customers, orders, invoices |
| warehouse | Warehouse staff | Products, inventory, purchase orders |
| accounting | Finance | Orders, invoices, payments, reports |
| viewer | Read-only user | Reports only, no edits |

## What to do

Add the 4 roles that don't exist yet: roaster, sales, warehouse, accounting, viewer.
Keep existing roles (admin, manager). The old "data-entry", "read-only", "reports" roles should be kept but the new roles cover the spec's requirement.

The task is to seed permissions for the 7 roles from the spec. So seed permissions for: admin, manager, roaster, sales, warehouse, accounting, viewer.

### 2. Seed table-level permissions for all 7 roles

Create a SQL seed file at `server/sql/step-41-seed-default-permissions.sql` that follows the Default Permission Matrix from the spec (Section 6.1):

| Table | Admin | Manager | Roaster | Sales | Warehouse | Accounting | Viewer |
|-------|-------|---------|---------|-------|-----------|------------|--------|
| Products | CRUD | CRUD | CRUD | R | R | R | R |
| Customers | CRUD | CRUD | - | CRUD | - | R | R |
| Orders | CRUD | CRUD | R | CRUD | R | R | R |
| Order Details | CRUD | CRUD | R | CRUD | R | R | R |
| Work Orders | CRUD | CRUD | CRUD | - | R | - | R |
| Inventory | CRUD | CRUD | R | - | CRUD | - | R |
| Employees | CRUD | CRUD | - | - | - | - | R |
| Suppliers | CRUD | CRUD | R | - | R | R | R |
| Invoices | CRUD | CRUD | - | - | - | CRUD | R |
| Financials | CRUD | R | - | - | - | CRUD | R |

(CRUD = can_select + can_insert + can_update + can_delete, R = can_select only)

Use the existing `shared.upsert_table_permission` helper function from step-34-seed-permissions.sql (it was DROPped at the end, so recreate it).

### 3. Seed field-level permissions

From the spec Section 6.2, seed field-level permissions for the Products table:

| Field | Admin | Manager | Roaster | Sales | Warehouse | Viewer |
|-------|-------|---------|---------|-------|-----------|-------|
| cost_price | RW | RW | RW | HIDDEN | HIDDEN | R |
| sell_price | RW | RW | RW | R | R | R |
| stock_qty | RW | RW | RW | HIDDEN | RW | R |
| reorder_level | RW | RW | RW | HIDDEN | RW | R |
| supplier_id | RW | RW | RW | HIDDEN | R | R |
| margin | RW | RW | RW | HIDDEN | HIDDEN | R |

Use the existing `shared.upsert_field_permission` helper function.

HIDDEN = can_read=false, can_write=false
R = can_read=true, can_write=false
RW = no explicit entry needed (defaults to readwrite)
