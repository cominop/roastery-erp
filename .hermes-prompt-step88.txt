### 1. Shell Scripts — `/home/fcc-student/Desktop/_DEV/roastery-ui/src/metadata/scripts/`

Create these CLI scripts that can be used in CI/CD pipelines:

#### `export-metadata.sh`
A shell script that:
1. Runs the exporter: `node server/metadata-exporter.cjs`
2. Runs the packager with metadata info: `node server/metadata-packager.cjs --description "<commit-message>" --source "<env>" --output deploy/erp_metadata_$(date +%Y-%m-%d).zip`
3. Commits the resulting .zip to git:
   ```bash
   git add deploy/erp_metadata_*.zip
   git commit -m "chore: metadata export $(date +%Y-%m-%d)"
   git tag "deploy/v$(node -e "console.log(require('./package.json').version)")"
   ```
4. Accept `--source` (dev/staging/prod) and `--message` (description) arguments
5. Handle errors gracefully — exit with code 1 on failure, print clear messages
6. Print the path to the generated archive on success

Usage:
```bash
./src/metadata/scripts/export-metadata.sh --source staging --message "Pre-deployment export"
./src/metadata/scripts/export-metadata.sh --help
```

#### `import-metadata.sh`
A shell script that:
1. Accepts an archive path: `--archive deploy/erp_metadata_2026-07-30.zip`
2. Validates first: `node server/metadata-importer.cjs --archive "$ARCHIVE"`
3. If validation fails, exits with error and suggests checking the archive
4. If validation passes, runs the full import:
   - Backup: `node server/metadata-backup.cjs --reason pre_import`
   - UPSERT: `node server/metadata-importer-upsert.cjs --archive "$ARCHIVE"`
5. Print summary of what was imported (forms, fields, events counts)
6. Accept `--skip-validation` flag for automated pipelines that validated separately

Usage:
```bash
./src/metadata/scripts/import-metadata.sh --archive deploy/erp_metadata_2026-07-30.zip
./src/metadata/scripts/import-metadata.sh --archive deploy/erp_metadata_2026-07-30.zip --skip-validation
```

#### `promote.sh`
A promotion pipeline script that combines export-import across environments:
1. Accepts: `--from dev --to staging` or `--from staging --to prod`
2. Runs `export-metadata.sh` on the source env (connects to source DB via env vars)
3. Transfers the archive (for now, just copies it locally — in a real setup this would be scp)
4. Runs `import-metadata.sh` on the target env
5. Prints a summary of the promotion

Usage:
```bash
./src/metadata/scripts/promote.sh --from dev --to staging
```

For now, since we're in a single-machine dev setup, the `promote.sh` script should:
- Export from the current database
- Copy the archive to `deploy/promotion-<env>-<date>.zip`
- Re-import (simulating a staging/prod import on the same DB)
- This is the pattern that would be extended for real multi-env promotion

### 2. GitHub Actions Workflow — `.github/workflows/metadata-deploy.yml`

Create a GitHub Actions workflow for automatic metadata deployment:

```yaml
name: Metadata Deploy

on:
  push:
    branches: [main, staging]
    paths:
      - 'src/metadata/export/definitions/*.json'
  workflow_dispatch:
    inputs:
      target:
        description: 'Deploy target'
        required: true
        default: 'staging'
        type: choice
        options:
          - staging
          - production

jobs:
  export:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Setup Node
        uses: actions/setup-node@v4
        with:
          node-version: 20
      - name: Export metadata
        run: |
          chmod +x src/metadata/scripts/export-metadata.sh
          ./src/metadata/scripts/export-metadata.sh --source ${{ github.ref_name }}
      - name: Upload archive
        uses: actions/upload-artifact@v4
        with:
          name: metadata-archive
          path: deploy/erp_metadata_*.zip

  import:
    needs: export
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Download archive
        uses: actions/download-artifact@v4
        with:
          name: metadata-archive
      - name: Import metadata
        env:
          DATABASE_URL: ${{ secrets[format('{0}_DATABASE_URL', github.ref_name)] }}
        run: |
          chmod +x src/metadata/scripts/import-metadata.sh
          ./src/metadata/scripts/import-metadata.sh --archive deploy/erp_metadata_*.zip
```

## Code Style & Guidelines

- Shell scripts: Bash scripts with `set -euo pipefail`, clear error handling, `--help` flag, color-coded output (green for success, red for error, yellow for warning)
- Use `#!/usr/bin/env bash` shebang
- Make scripts executable: `chmod +x`
- Use consistent indentation (2 spaces for YAML, 4 spaces for scripts where it matters)
- Keep the GitHub Actions workflow simple — it documents the intended CI pattern even if the self-hosted runner doesn't have all secrets configured yet
- All scripts should work standalone (just need node and the codebase)
