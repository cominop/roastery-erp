Implement Step 31: Smart default suggestions (per field pattern)

This is part of the Filtering spec (Track C, step 8 of 9).

## Context

The Roastery ERP has a complete filter system (FilterPanel, type-specific controls, URL persistence, quick filters, saved presets). The filter panel currently requires users to manually select which columns to filter on. 

Step 31 adds **smart default suggestions** — when any data table/form opens, the system analyzes the field definitions and automatically suggests the most useful filters, pre-selected and ready to use.

## What to Build

### 1. Server-side: `src/filters/server/filter_suggestions.py`
Create a Python module that accepts a list of field definitions (from the metadata API) and returns suggested filters based on field name patterns:

| Field name pattern | Suggested filter type |
|---|---|
| `*_date`, `*_at`, `date_*` | Date range |
| `status`, `state`, `type` | Dropdown equals |
| `*_id`, `*_by` | Lookup dropdown |
| `name`, `title`, `description` | Text contains |
| `price`, `cost`, `total`, `amount` | Currency range (number) |
| `qty`, `count`, `stock` | Number range |
| `is_*`, `has_*`, `active` | Boolean dropdown |

The function signature should be:
```python
from typing import Any

def suggest_filters(fields: list[dict[str, Any]]) -> list[dict[str, Any]]:
    """
    Given a list of field definitions (from the form metadata API),
    return a list of suggested filter definitions, ordered by relevance.
    
    Each field dict has keys: name, type, caption, is_lookup, lookup_source (optional)
    Each returned suggestion has keys: fieldName, caption, filterType, defaultValue (optional)
    """
```

Create an API endpoint at `/api/filters/suggestions/{table_name}` that:
- Fetches field definitions from the metadata API for the given table
- Calls `suggest_filters()` 
- Returns the suggestions as JSON

### 2. Client-side: `src/filters/useFilterSuggestions.ts`
React hook that:
- Takes a `tableName` and field definitions
- Fetches suggestions from `/api/filters/suggestions/{tableName}`
- Returns `{ suggestions: FilterSuggestion[], loading: boolean, error: string | null }`
- Caches suggestions per table (no repeated fetches)
- Includes a `regenerate()` method to force refresh

```typescript
interface FilterSuggestion {
  fieldName: string;
  caption: string;
  filterType: 'date_range' | 'equals_dropdown' | 'lookup_dropdown' | 'text_contains' | 'number_range' | 'currency_range' | 'boolean_dropdown';
  defaultValue?: any;
}
```

### 3. Client-side: `src/filters/FilterSuggestionsBar.tsx`
A React component that:
- Renders as a horizontal bar of suggestion chips above the filter panel
- Each chip shows the field caption and the filter type (e.g. "Status: [Dropdown equals]")
- Clicking a chip activates that filter in the filter panel
- Has a "Show all suggestions" button to expand/collapse when there are >5 suggestions
- Has a "Dismiss" (X) button on each suggestion to remove it

### 4. Integration: Update `FilterPanel.tsx`
- Import and render `FilterSuggestionsBar` above the existing filter controls
- When a suggestion chip is clicked, call the existing `addFilter()` function with the correct column definition and default filter type
- Add a "Suggestions" collapsible section header

## Implementation Notes

1. The suggestion logic should be **pattern-based only** — no AI/ML. Simple regex/glob matching against field names.
2. For the server-side Python code, the existing backend uses FastAPI. Look at existing API endpoints for patterns.
3. The `FilterColumn` type in `src/filters/types.ts` uses: `field`, `label`, `type` (text|number|date|boolean|lookup), and optional `lookupSource`. The suggestion system should convert field definitions to `FilterColumn` objects.
4. Suggestions should NOT auto-activate filters — they show what's available for one-click activation.
5. The suggestions bar should appear in both collapsed and expanded filter panel states.
6. If a suggestion is dismissed, it should be stored in localStorage so it doesn't re-appear on next page load.
