# Step 86 — Metadata Deployment 7: Rollback from backup

## Objective
Implement the rollback-from-backup functionality. When a metadata import goes wrong, the user should be able to roll back to a previous state using one of the auto-generated backup archives.

## What already exists

### Server-side (already built in previous steps):
1. **`server/metadata-backup.cjs`** — Creates metadata backups (exports metadata + zips it + records in `shared.metadata_backups`)
2. **`server/metadata-exporter.cjs`** — Exports metadata from DB to JSON files
3. **`server/metadata-packager.cjs`** — Packages JSON files into .zip with manifest + checksums
4. **`server/metadata-importer.cjs`** — Validates manifest + checksums of an archive
5. **`server/metadata-importer-upsert.cjs`** — UPSERTS metadata into database tables
6. **`server/sql/step-85-metadata-backups.sql`** — Created `shared.metadata_backups` table (id UUID PK, path TEXT, created_at TIMESTAMP, reason TEXT, size_bytes BIGINT, checksum TEXT NOT NULL)
7. **API endpoints already in `server/index.cjs`:**
   - `POST /api/metadata/backup` — creates a backup
   - `GET /api/metadata/backups` — lists all backups (supports ?limit=N, ?reason=pre_import)
   - No rollback endpoint exists yet

### Frontend-side (already built):
- **`src/metadata/components/DiffPreview.tsx`** — Diff comparison component exists
- **`src/metadata/__tests__/DiffPreview.test.tsx`** — Tests for DiffPreview
- **No `BackupList.tsx` component exists yet**
- **No `MetadataManager.tsx` page component exists yet** (the main page that ties together DiffPreview, Export, Import, and BackupList)

## What needs to be built

### 1. Create `server/metadata-rollback.cjs`
A CLI script that restores metadata from a backup archive. Requirements:
- Accept `--backup-path <path>` to specify which backup to restore from
- Accept `--backup-id <uuid>` to look up the backup from the DB (reads path from `shared.metadata_backups`)
- Validate the backup archive using the same manifest/checksum validation logic from `metadata-importer.cjs`
- Extract the archive to a temp directory
- Call the UPSERT importer (`metadata-importer-upsert.cjs`) to apply the metadata
- Update the `metadata_backups` record: set `reason = 'rolled_back'` or add a `rollback_at` timestamp — actually, since the table schema is just `(id, path, created_at, reason, size_bytes, checksum)`, you can either:
  - Add a `rolled_back_at TIMESTAMP` column via ALTER TABLE (safe migration)
  - Or just record the rollback in `metadata_imports` table (which has `rollback_at` and `rollback_by` columns) — but check if that table exists first
- Output machine-readable JSON with `--json` flag
- Support `--dry-run` to validate without applying
- On success: return the backup details + success message

### 2. Add API endpoints to `server/index.cjs`
Add these routes:

**A) `POST /api/metadata/rollback/:backupId`**
- Looks up the backup by ID from `shared.metadata_backups`
- Calls `metadata-rollback.cjs --backup-id <id> --json`
- Returns the rollback result
- If the backup path doesn't exist on disk, return 400

**B) `POST /api/metadata/rollback/upload`** (optional but useful)
- Accepts a file upload (multipart) — an external .zip backup file
- Saves it to a temp location
- Runs rollback validation
- Returns preview of what would be restored

### 3. Create `src/metadata/components/BackupList.tsx`
A React component that displays available backups and allows rollback. Requirements:
- Fetches backups from `GET /api/metadata/backups`
- Displays a table/list with: date, size, reason, checksum (truncated)
- Each row has a "Rollback to this" button
- Clicking the button shows a confirmation dialog: "⚠️ This will replace ALL current metadata with the state from this backup. Current metadata will be backed up automatically. Continue?"
- On confirm: calls `POST /api/metadata/rollback/:backupId`
- Shows loading state during rollback
- Shows success/error toast or inline status
- Handles error states (backup file missing, server error, etc.)
- Style: use the same patterns as DiffPreview.tsx (shadcn/ui, Tailwind classes)

### 4. Create `MetadataManager.tsx` page
Since there's no main metadata page yet, create `src/metadata/MetadataManager.tsx`:
- A tabbed or sectioned page with:
  - **Backups tab**: shows `<BackupList />`
  - **Diff tab**: shows `<DiffPreview />` (already exists)
  - **Export tab**: placeholder linking to the POST /api/metadata/backup API
  - **Import tab**: placeholder for future import dialog
- Use shadcn Tabs component
- Add a route to it (check how other pages are routed in the app)
- Add it to the sidebar navigation (check `nav_tree` or sidebar component)

### 5. Update `server/metadata-backup.cjs` to add `rolled_back_at` column
Actually, instead of ALTER TABLE, just check if `metadata_imports` table exists (from the spec in section 9) and record the rollback there. If it doesn't exist, create it:

```sql
CREATE TABLE IF NOT EXISTS shared.metadata_imports (
  id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  filename        TEXT NOT NULL,
  checksum        TEXT NOT NULL,
  imported_by     UUID,
  imported_at     TIMESTAMP DEFAULT NOW(),
  status          TEXT DEFAULT 'completed' CHECK (status IN ('pending', 'importing', 'completed', 'failed', 'rolled_back')),
  backup_path     TEXT,
  rollback_at     TIMESTAMP,
  rollback_backup_id UUID REFERENCES shared.metadata_backups(id),
  error_log       TEXT,
  import_log      TEXT
);
```

## Important notes

1. **Shell escaping**: Use the `--json` flag for machine-readable output from CLI scripts; parse JSON in the API handler
2. **Dev servers**: If you modify `server/index.cjs`, the API server will restart automatically via nodemon/nodemon-like behavior. If it crashes, restart it with `node server/index.cjs &`
3. **Database**: The project uses PostgreSQL with database `polyaccess` and schema `shared`. The pool connects via `new Pool({ database: "polyaccess" })`
4. **Existing patterns**: Look at `metadata-backup.cjs` for the CLI script pattern (arg parsing, logging, json output, error handling)
5. **Frontend patterns**: Look at DiffPreview.tsx for the existing component pattern (React, shadcn/ui, Tailwind, types)
